# GSM Developer SRL — сайт-визитка 1С с личными кабинетами

Сайт-визитка компании услуг 1С с личными кабинетами **клиентов** и **администратора**.
Клиенты создают заявки на доработку (с вложениями, статусом и перепиской), администратор
ведёт все заявки, меняет статусы и назначает исполнителей. Новые заявки прилетают в **Telegram**.

**Стек:** Next.js 15 (App Router) · TypeScript · Tailwind CSS · Supabase (Postgres + Auth) ·
хостинг Vercel · уведомления через Telegram-бота.

---

## Что нужно (аккаунты)

1. [Supabase](https://supabase.com) — база данных и вход (бесплатный тариф подходит).
2. [Vercel](https://vercel.com) — хостинг (бесплатный тариф подходит).
3. [Telegram](https://telegram.org) — бот для уведомлений (необязательно, можно позже).
4. [Node.js 18+](https://nodejs.org) — для локального запуска.

## Шаг 1. Установка и локальный запуск

```bash
npm install
```

Скопируйте файл переменных окружения и заполните его на шаге 2:

```bash
cp .env.local.example .env.local
```

Запуск в режиме разработки:

```bash
npm run dev
```

Откройте <http://localhost:3000>.

## Шаг 2. Настройка Supabase (база данных)

1. Зайдите на <https://supabase.com> → **New project**. Придумайте название и **пароль базы**
   (сохраните его). Дождитесь создания проекта (~2 минуты).
2. Слева откройте **SQL Editor** → **New query**. Скопируйте туда **весь** файл
   [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**. Это создаст таблицы,
   правила доступа (RLS) и триггеры.
3. (По желанию) Так же выполните [`supabase/seed.sql`](supabase/seed.sql) — он добавит
   демо-компании и 5 примеров заявок, чтобы кабинет админа был не пустым.
4. Откройте **Project Settings → API** и скопируйте в `.env.local`:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` ключ → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` ключ → `SUPABASE_SERVICE_ROLE_KEY` (секретный, только для сервера)
5. **Отключение подтверждения email (для быстрого старта):**
   **Authentication → Providers → Email** → выключите «Confirm email». Тогда после регистрации
   вход происходит сразу. Если оставить включённым — пользователь получит письмо со ссылкой.

Перезапустите `npm run dev` после заполнения `.env.local`.

---

## Шаг 3. Создание первого администратора

Роли назначаются вручную — это защита от того, чтобы посторонний сделал себя админом.

1. Зарегистрируйтесь на сайте (`/login` → «Зарегистрироваться»): укажите имя, компанию, email, пароль.
2. В Supabase → **SQL Editor** выполните (подставьте свой email):

   ```sql
   update public.profiles
   set role = 'admin'
   where id = (select id from auth.users where email = 'ВАШ_EMAIL');
   ```

3. Выйдите и войдите снова — откроется кабинет администратора со всеми заявками.

> Клиенты регистрируются сами и автоматически привязываются к своей компании
> (по названию, которое ввели при регистрации). Одна компания — общие заявки для её сотрудников.

## Шаг 4. Уведомления в Telegram (бот randan.com)

1. В Telegram напишите [@BotFather](https://t.me/BotFather) → `/newbot` → получите **токен** бота.
2. Узнайте **chat_id**, куда слать уведомления:
   - для личного чата: напишите что-нибудь боту, затем откройте
     `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — там будет `chat.id`;
   - для канала/группы: добавьте бота в него и возьмите `chat_id` (для каналов начинается с `-100`).
3. Заполните в `.env.local` (и позже в Vercel):
   - `TELEGRAM_BOT_TOKEN` — токен от BotFather
   - `TELEGRAM_CHAT_ID` — id чата/канала

Если переменные пустые — сайт работает как обычно, просто без уведомлений.

---

## Шаг 5. Деплой на Vercel

1. Загрузите проект в репозиторий GitHub (или используйте `vercel` CLI).
2. На <https://vercel.com> → **Add New → Project** → выберите репозиторий. Framework определится
   как **Next.js** автоматически.
3. В **Environment Variables** добавьте те же переменные, что в `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY`
   - `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (если используете)
   - `NEXT_PUBLIC_SITE_URL` — адрес сайта на Vercel, например `https://gsm.vercel.app`
4. Нажмите **Deploy**.
5. В Supabase → **Authentication → URL Configuration** добавьте адрес Vercel в
   **Site URL** и **Redirect URLs** (чтобы работали письма-подтверждения).

## Структура проекта

```
supabase/
  schema.sql            таблицы, RLS-политики, триггеры
  seed.sql              демо-данные (необязательно)
src/
  app/
    page.tsx            лендинг (визитка)
    actions.ts          приём заявки с формы лендинга
    login/              вход и регистрация (Supabase Auth)
    dashboard/          личный кабинет (клиент/админ) + серверные действия
  components/
    Logo.tsx
    landing/LeadForm.tsx
    dashboard/          Dashboard, TicketList (аккордеон), NewTicketModal
  lib/
    supabase/           клиенты Supabase (browser/server/admin/middleware)
    notify.ts           уведомления в Telegram
    types.ts, constants.ts
  middleware.ts         защита /dashboard и обновление сессии
```

## Роли и доступ

- **Клиент** — видит и создаёт заявки только своей компании, добавляет комментарии и вложения.
- **Администратор** — видит все заявки всех компаний, меняет статус и исполнителя, отвечает в переписке.
- Разграничение доступа обеспечено на уровне базы (Row Level Security) — клиент физически
  не может получить чужие данные, даже в обход интерфейса.
